# AI SDR — план

Обновлено: 2026-10-07. Предыдущая версия плана (работа с Codex) — в истории git, коммит `5f9a130`.

## Цель

Портфолио-проект для фриланса: рабочее веб-приложение, которое исследует компанию и готовит обоснованное персонализированное письмо. Пользователь задаёт компанию, своё предложение, роль получателя, язык и тон; получает факты с источниками, подход, редактируемое письмо, время каждого этапа и стоимость запуска.

Стек: React + TypeScript + Vite → FastAPI (SSE) → LangGraph. Хранение — SQLite.

Не входит: автоматическая рассылка, CRM, аккаунты, оплата.

## Принятые решения

- **Доступ:** публичная версия открыта без регистрации. Защита — лимит запусков с одного адреса, один одновременный запуск на адрес и суточный потолок расходов на весь сервис. Аккаунты, пробные попытки и оплата не делаются.
- **Модели:** только OpenAI. База — текущая `gpt-5.4-mini`; кандидаты выбираются на этапе 5 по актуальному каталогу.
- **Хостинг:** решаем на этапе 6. До этого приложение делается переносимым: один Docker-образ, FastAPI отдаёт API и собранный фронтенд.
- **Примеры:** финальные видео для Examples записывает пользователь на работающем сервисе (этап 6). Текущие ролики — временные, на вымышленных данных.
- **Принцип:** сначала сквозной рабочий сценарий на реальных данных, потом учёт, качество и публикация.

## Этап 2 — Ядро

Цель: граф даёт честный, структурированный результат по полному брифу и проверяется тестами без платных вызовов.

1. **Вход.** `SDRState` принимает весь бриф: `company`, `website`, `offer`, `recipient`, `language`, `tone`.
2. **Структурированные результаты** (Pydantic, structured output вместо разбора JSON из текста):
   - Research → список фактов `{claim, source_url, source_title, excerpt}` и флаг достаточности данных;
   - Strategy → подход: наблюдение о компании, связь с `offer`, гипотезы (явно помечены);
   - Copywriter → `{subject, body}` на нужном языке и в нужном тоне;
   - Review → `{passed, issues}`.
3. **Исследование.** Несколько запросов Tavily (о компании, продукт, новости), URL сохраняются; проверка, что найдено именно то, что указано в `website`; отдельный путь «недостаточно данных» вместо выдумывания.
4. **Честные статусы.** Итог запуска — `ready`, `needs_attention` (исчерпаны переписывания, но черновик есть) или `failed`. Ошибка LLM или разбора не превращается в текст результата и не считается прохождением проверки.
5. **Переписывание** получает предыдущий черновик и замечания, а не только замечания. Лимит попыток — в конфигурации.
6. **Промпты** — в отдельных файлах с версией; версия сохраняется вместе с результатом.
7. **Слой LLM.** Модель и параметры задаются по этапам в конфигурации. Каждый вызов отдаёт usage из метаданных API (для этапа 4).
8. **События.** Узлы графа публикуют события в формате контракта фронтенда (`frontend/src/run.ts`): `stage` с `elapsedMs`, `evidence`, `draft_delta`, `completed`/`failed`.
9. **Тесты** (pytest): фейковые LLM и поиск; проверить ложный успех, лимит переписываний, недостаток данных, неверный сайт, формат событий.

Готово, когда: все тесты проходят без сети; один ручной запуск через CLI (с согласия пользователя, платно) даёт факты с URL, подход и письмо на выбранном языке.

Сделано (2026-10-07):

- Граф `researcher → strategist → copywriter ⇄ reviewer`, ранний выход при `insufficient_data` / `website_mismatch`. Итог и причина решаются в `core/runner.py`; любое исключение — `failed`, не результат.
- Research: три запроса Tavily (сайт через `include_domains`, открытый веб, новости), дедупликация, факт сохраняется только если его цитата дословно есть в источнике.
- Strategy возвращает `offer_fit`; при `poor` письмо пишется, но итог — `needs_attention`.
- Промпты — `prompts/*.md` с версией; usage каждого вызова (и неудачного) и кредиты Tavily пишутся в результат.
- Контракт событий расширен и синхронизирован с `frontend/src/run.ts`: `activity`, `strategy`, `draft_reset`, `review`, исход в `completed`, причина в `failed`; время этапа накапливается между повторами при переписывании.
- Streamlit заменён на `python -m core.cli`. `app.py` удалён; пакеты `streamlit`, `langchain-community`, `langchain-tavily` убраны из `requirements.txt`.
- `temperature` больше не передаётся; по этапам задаётся `reasoning_effort` — `gpt-5.4-mini` его принимает.
- Ручной запуск (Linear, linear.app, offer — рекрутинг участников интервью, Head of Product, English/Direct): `ready` с первой попытки, 5 фактов с URL (3 отброшены проверкой цитат), 4 вызова LLM ≈ 5,6 тыс. входных и 1,5 тыс. выходных токенов, 3 кредита Tavily, 19 с.

Ручной запуск на том же брифе Linear: `ready` с первой попытки, 6 фактов с URL, 4 вызова LLM ≈ 5,7 тыс. входных и 1,9 тыс. выходных токенов (reasoning заполнен), 3 кредита Tavily, 16 с — structured output, usage и кредиты на новых версиях работают.

1. **FastAPI:**
   - `POST /api/runs` — бриф, валидация, возвращает `run_id`;
   - `GET /api/runs/{id}/events` — SSE с `sequence`, повтор пропущенного по `Last-Event-ID`;
   - `POST /api/runs/{id}/cancel`;
   - `GET /api/runs/{id}` — снимок состояния для восстановления после перезагрузки.
2. **Стриминг письма** токенами из copywriter в `draft_delta`.
3. **SQLite:** таблицы `runs`, `events`, `llm_calls`; миграции.
4. **Фронтенд:** транспорт SSE поверх `reduceRun`, рабочая кнопка Generate с валидацией брифа, отмена, восстановление текущего запуска после перезагрузки, понятные ошибки.
5. **Лимиты доступа:** не больше N запусков в час с одного адреса, один одновременный запуск на адрес.
6. **Разработка:** одна команда поднимает API и Vite (прокси `/api`).
7. **Тесты:** API на фейковом графе; e2e Playwright на фейковом сервере.

Готово, когда: в браузере проходит полный запуск с живыми этапами и стримингом письма, перезагрузка страницы не теряет результат.

Сделано (2026-10-07), шаги 1–7:

- **API** (`server/`): `POST /api/runs` (валидация брифа, 201 / 422 / 429), SSE `GET /api/runs/{id}/events` на встроенном `fastapi.sse` — повтор с `?after=` или `Last-Event-ID`, затем живые события, поток закрывается после `completed`/`failed`; `POST /api/runs/{id}/cancel` (202 / 409); снимок `GET /api/runs/{id}` (бриф, статус, последний `sequence`). Граф выполняется в пуле потоков, SSE будится через `call_soon_threadsafe`.
- **Отмена** кооперативная: флаг проверяется перед каждым платным вызовом, уже идущий вызов дорабатывает и учитывается. Итог — `failed` с новой причиной `cancelled`; отмена после последнего вызова не портит готовый результат. В UI отмена нейтральная, не авария.
- **SQLite** вместе с API (шаги 1 и 3 объединены: повтор событий и восстановление всё равно требуют хранилища): `runs`, `events`, `llm_calls`, `search_calls`, миграции через `PRAGMA user_version`. Терминальное событие пишется в одной транзакции с итогом. Запуски, оставшиеся `running` после рестарта или упавшие вне графа, закрываются событиями `started`+`failed`, клиент не зависает.
- **Стриминг письма**: copywriter стримит strict JSON-schema ответ, частичный JSON → `draft_delta`; usage берётся из финального чанка, не суммируется. Пробелы по краям придерживаются, склейка дельт совпадает с итоговым письмом, иначе `draft_reset`. `OpenAILLM` проверяется офлайн на mock-транспорте. Попутно исправлено: при обрыве по лимиту длины usage терялся — теперь берётся из исключения SDK.
- **Лимиты**: один запуск одновременно и `SDR_RUNS_PER_HOUR` (5) в час на адрес; адрес хранится солёным хэшем; 429 с понятным текстом и `Retry-After`.
- **Фронтенд**: `api.ts` (валидация брифа зеркально серверной, проверка формы событий, отброс чужих и битых событий до reducer'а), `useRun.ts` (запуск, отмена, id запуска в `localStorage` и повтор событий после перезагрузки, проверка сервиса с повтором раз в 15 с). Generate активна, когда сервис доступен; ошибки полей показываются по нажатию, а не скрываются за неактивной кнопкой. Во время запуска форма заблокирована, кнопка становится Cancel run.
- **Разработка**: `npm.cmd run dev:all` поднимает uvicorn с reload и Vite с прокси `/api`.
- **Тесты**: API на фейковом графе (поток, повтор, отмена, лимиты, рестарт, сбой вне графа); e2e Playwright на `tests/fake_server.py` — полный запуск, перезагрузка посреди запуска, отмена, сбой, невалидный бриф, недоступный сервис.

Живой запуск в браузере (тот же бриф Linear, перезагрузка страницы посреди Research): `ready` с первой попытки, 6 фактов, 110 событий `draft_delta`, склейка которых совпала с итоговым письмом; 4 вызова LLM ≈ 6,3 тыс. входных и 2,0 тыс. выходных токенов, usage стримингового вызова Writing получен полностью (включая reasoning); 3 кредита Tavily; всё записано в SQLite. Время 30 с против 16 с в CLI — разброс задержки OpenAI (Strategy 8 с), не накладные расходы API.

## Этап 4 — Учёт usage, стоимости и лимиты

- Токены каждого вызова из метаданных API: вход, кэшированный вход (часть входа), выход, reasoning (часть выхода). Ничего не считается дважды.
- Поиск: число операций Tavily и их стоимость отдельно.
- Таблица тарифов с датой и версией; стоимость каждого вызова фиксируется при записи и не пересчитывается задним числом.
- Неизвестное — прочерк и пометка «неполные данные», не ноль. Суммы — расчётные, не счёт провайдера.
- Окно Run costs получает реальные данные: «этот запуск», 24 часа, 30 дней; разбивка по этапам и попыткам.
- **Суточный потолок расходов:** проверка перед каждым вызовом; при превышении новые запуски отклоняются с понятным сообщением.
- Тесты: арифметика тарифов, отсутствие двойного учёта, агрегация за период, неизвестный usage, срабатывание потолка.

Решения (2026-10-07): Tavily на бесплатном плане (1000 кредитов в месяц, сброс 1-го числа; basic search = 1 кредит), но поиск оценивается по тарифу pay-as-you-go $0.008 за кредит — так видна реальная себестоимость. Сначала был суточный потолок; по решению пользователя заменён месячным, потому что квота Tavily месячная:

- **Сервис**, календарный месяц UTC: $5 на модели (реальные деньги) и 750 кредитов Tavily (≈ 250 запусков; ≈ 250 кредитов остаётся на CLI и этап 5). При исчерпании — крупное объявление «Service temporarily stopped by the developer» без даты: когда сервис вернётся, решает разработчик. Счётчики календарные, поэтому 1-го числа приём запусков открывается сам.
- **Посетитель**, по адресу: 3 запуска за 24 часа и 10 за 30 дней, один одновременно. Устройство без аккаунтов не опознать (id в браузере сбрасывается инкогнито), поэтому ограничение — по адресу; за общим адресом (мобильный оператор, офис) квота общая.
- **Разработчик** — без ограничений: ключ `SDR_DEVELOPER_KEY`, один раз открыть сайт по ссылке `/#developer=<ключ>` (фрагмент не уходит на сервер), ключ хранится в браузере и отправляется заголовком `X-Developer-Key`. Не действуют квота, пауза, «один запуск одновременно» и проверка бюджета перед вызовами; расходы разработчика учитываются в бюджете. Без ключа в окружении режим выключен.
- Цены в интерфейсе — как если бы Tavily был платным: поиск по тарифу pay-as-you-go.
- Принятый риск: без суточного потолка наплыв в один день может выбрать месяц целиком — тогда сервис стоит на паузе до 1-го.

Сделано (2026-10-07):

- **Тарифы** — `core/pricing.py`, версия `2026-10-07` по официальным страницам OpenAI и Tavily: `gpt-5.4-mini` $0.75 / $0.075 кэш / $4.50 за 1M токенов, `gpt-5.4-nano` $0.20 / $0.02 / $1.25. Имя снапшота (`gpt-5.4-mini-2026-03-17`) сводится к базовому. Кэшированный вход — часть входа и оценивается один раз; reasoning — часть выхода и не добавляется. Неизвестная модель или неполный usage — стоимость `None`.
- **Стоимость при записи**: `RunContext` считает стоимость и версию тарифа в момент записи вызова (и неудачного — с usage из ошибки) и сразу отдаёт вызов в `on_record`; сервер пишет его в SQLite немедленно, а не в конце запуска. Миграция 2: `cost_usd` и `price_version` у вызовов, `duration_ms` у запуска, индексы по `created_at`. Вызовы этапа 3 остались без стоимости — задним числом ничего не пересчитано.
- **Месячный бюджет** (`SDR_MONTHLY_MODEL_USD`, `SDR_MONTHLY_SEARCH_CREDITS`): новый запуск принимается, только если помещается вместе с резервом ($0.05 и 3 кредита) на каждый идущий запуск, иначе 429 «The service is temporarily stopped by the developer.» без `Retry-After`. Перед каждым платным вызовом проверка повторяется; при исчерпании запуск завершается `failed` с причиной `budget_exhausted`. Поиск без сообщённых кредитов считается за один кредит.
- **Квота посетителя** (`SDR_RUNS_PER_DAY`, `SDR_RUNS_PER_MONTH`) заменила почасовой лимит; отказ называет, когда будет следующий запуск. `GET /api/status` отдаёт паузу сервиса и квоту; фронтенд показывает остаток запусков под кнопкой, выключает Generate при исчерпании и показывает объявление о паузе над брифом.
- **API**: `GET /api/runs/{id}/usage` — итоги и каждый вызов; `GET /api/usage?period=24h|30d` — запуски посетителя за период и состояние бюджета сервиса за месяц. Итог суммирует известное; `null`, если не известно ничего; флаг `incomplete`, если известно не всё.
- **Окно Run costs** на реальных данных: «этот запуск» с разбивкой по шагам и черновикам (поиск отдельно, сбойные вызовы помечены), 24 часа и 30 дней по адресу посетителя, строка бюджета сервиса, предупреждение о неполных данных. Обновляется по мере прохождения этапов. CLI печатает оценку стоимости.
- **Тесты**: 87 pytest (арифметика тарифов, двойной учёт, неизвестный usage, агрегация по периодам и клиентам, квоты за сутки и месяц, пауза по кредитам и деньгам, прошлый месяц не считается, резерв идущих запусков, остановка посреди запуска), 34 Vitest, 13 e2e. Окно стоимости и объявление о паузе проверены визуально на 1440 и 390 px, в светлой и тёмной теме.
- **Живой запуск** в браузере (бриф Linear, рекрутинг участников интервью, Head of Product): `ready` с первой попытки за 24 с; 4 вызова LLM — 5 608 входных (0 кэшированных) и 1 864 выходных (997 reasoning) токенов, модель $0.0126; 3 кредита Tavily — $0.024 по тарифу PAYG; итого $0.0366. Ручная сверка по тарифу сошлась. Каждый вызов записан в момент своего завершения; квота показала «1 today, 8 this month»; за 30 дней — пометка о неполных данных из-за запуска этапа 3 без стоимости.

## Этап 5 — Качество и выбор моделей

- Набор из 20–30 случаев: известные и маленькие компании, неоднозначные названия, мало информации, неверный сайт, неподходящее предложение, английский и русский. Часть случаев отложить для финальной проверки.
- Источники сохраняются снимком, чтобы модели сравнивались на одинаковых данных; живой поиск проверяется отдельно.
- CLI-скрипт прогоняет набор с заданной конфигурацией моделей и сохраняет результаты, время и стоимость.

## Открытые вопросы после этапа 2

- UI для структурной стратегии (гипотезы, `offerFit`), замечаний review и состояния `needs_attention` по-прежнему минимальный — в этапе 3 приоритетом был сквозной сценарий; кандидат в начало этапа 4 или 5.
- Живой таймер этапа после перезагрузки считает от момента перезагрузки, а не от начала этапа (итоговые тайминги — серверные и точные).
- Сообщение `failed` для клиента общее; подробности ошибки остаются в результате на сервере.
- В ручном запуске письмо прошло review, но предлагает «интервью с клиентами из Customer Requests» — связь offer с наблюдением натянута. Review пока не проверяет логику предложения; кандидат в набор этапа 5.
- В живом запуске этапа 3 письмо пишет «more than 40,000 organizations across multiple sectors», а факт — «over 40,000 product teams»: review не ловит искажение фактов. Кандидат в набор этапа 5.
- Поле тела письма после завершения имеет фиксированную высоту (7 строк), письмо из 90 слов прокручивается внутри — стоит сделать автоувеличение.
- Порог проверки цитат (дословное совпадение после нормализации) может отсекать перефразированные факты — оценить на наборе этапа 5.
