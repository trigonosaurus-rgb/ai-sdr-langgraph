# AI SDR — план

Обновлено: 2026-10-07. Предыдущая версия плана (работа с Codex) — в истории git, коммит `5f9a130`.

## Цель

Портфолио-проект для фриланса: рабочее веб-приложение, которое исследует компанию и готовит обоснованное персонализированное письмо. Пользователь задаёт компанию, своё предложение, роль получателя, язык и тон; получает факты с источниками, стратегию, редактируемое письмо и прозрачные время и стоимость запуска.

Стек: React + TypeScript + Vite → FastAPI (SSE) → LangGraph. Хранение — SQLite.

Не входит в первую версию: автоматическая рассылка, CRM, командные аккаунты.

## Принцип порядка

Сначала сквозной рабочий сценарий на реальных данных, потом учёт, качество и публикация. Интерфейс без реальных данных шлифуем ограниченно: реальные ответы покажут, что ему действительно нужно.

## Известные проблемы ядра (для этапа 2)

- `spam_checker` при достижении лимита попыток и при ошибке парсинга JSON возвращает «не спам» — письмо выглядит прошедшим проверку.
- Ошибки LLM в strategist/copywriter превращаются в текст `Error ...`, который уходит дальше по графу как результат.
- Researcher делает один поиск и передаёт дальше только сводку: URL источников теряются.
- Стратегия не знает, что продаёт пользователь (`offer`), роль получателя, язык и тон.
- При переписывании copywriter не видит предыдущий черновик, только фидбек.
- Нет учёта токенов и стоимости.

## Принципы учёта (для этапа 4)

- Usage берётся из метаданных API, не из длины текста. Reasoning-токены — часть выходных, кэшированные — часть входных; не считать их дважды.
- Неизвестное — это прочерк и пометка «неполные данные», а не ноль.
- Стоимость LLM и поиска (Tavily) отдельно, затем итог. Суммы — расчётные, не счёт провайдера. Тарифы фиксировать с датой и версией, исторические расходы молча не пересчитывать.
- Учитывать все вызовы, включая переписывания и неудачные попытки. Время хранится в UTC.

## Модели (для этапа 5)

База сравнения — текущая `gpt-5.4-mini`. Кандидатов выбрать при начале этапа по актуальному каталогу и тарифам провайдера. Модель не меняется ради новизны: решение — по качеству, цене успешного результата и задержке на одинаковых данных.

## Проверка качества (для этапа 5)

20–30 случаев: известные и маленькие компании, неоднозначные названия, мало информации, неверный сайт, продукт не подходит компании, разные языки. Часть случаев отложить для финальной проверки. Для сравнения моделей — одинаковые сохранённые источники. Метрики: подтверждаемость фактов, релевантность, естественность письма, корректность отказов, частота ошибок, время, стоимость. Оценку того же LLM не выдавать за независимое доказательство качества; рост конверсии не заявлять без реальной кампании.
